\section{Case Study}
\label{sec:case-study}

This section walks through concrete reference systems and buildable implementations for a systems engineering audience. The narrative has three parts:
\begin{enumerate}
    \item \textbf{Basic kit.} Four Nat-valued shelf zones---an incrementing counter, a saturating subtracter, a clear/add accumulator, and a zero-test branch---each presented as a reference table $Z_{\text{spec}}$, a compiled dynamics-encoding fragment $\Phi_{\mathrm{dyn}}$, and one direct buildable $Z_{\text{impl}}$.
    \item \textbf{Alternate buildables.} The same reference tables are held fixed while buildable encodings change (binary-shift counter; instrumented decrement; two zero-test latches). At each change we contrast assertional re-checking of the compiled fragment against classical reconstruction of a Wymore system homomorphism $h=(h_S,h_I,h_O)$.
    \item \textbf{Composition surprise.} The kit already contains the ingredients of a register machine. Wiring those shelf buildables yields a Fibonacci system: on receipt of $n\in\mathbb{N}$, output the $n$th Fibonacci number.
\end{enumerate}
For readers less familiar with T3SD: a \emph{reference system} $Z_{\text{spec}}$ is a complete discrete-system table (states, inputs, outputs, next-state, readout) that expresses required behavior. A \emph{buildable system} $Z_{\text{impl}}$ is another such table---often with richer internal state---that is intended to realize the same behavior. Classical checking asks for a homomorphism from $Z_{\text{impl}}$ onto $Z_{\text{spec}}$. Here we instead compile $\Phi_{\mathrm{dyn}}$ from $Z_{\text{spec}}$ and check that property set on each buildable.

The case studies are qualitative on verification effort---they exhibit a stable fragment beside evolving buildables and an honest kit-bound composition; they do not measure wall-clock cost. State spaces are infinite discrete ($\mathbb{N}$); maps are exhibited and verified by hand rather than discovered by search.
