\section{Case Study}
\label{sec:case-study}

This section walks through concrete reference systems and buildable implementations for a systems engineering audience. Each example follows the same \emph{lifecycle} shape:
\begin{enumerate}
    \item State the required behavior in plain language and as a discrete-system table $Z_{\text{spec}}$.
    \item Compile the dynamics-encoding property set $\Phi_{\mathrm{dyn}}$ from that table once (Section~\ref{sec:dynamics-encoding-fragment}).
    \item Treat successive buildables as iterations of the system-as-built:
    \begin{itemize}
        \item \textbf{v1 --- prototype:} a near-direct realization of $Z_{\text{spec}}$ (baseline).
        \item \textbf{v2 --- instrumented build:} richer internal state (logging, parallel counters) that still projects cleanly onto $Z_{\text{spec}}$.
        \item \textbf{v3 --- structural refactor:} a more substantial change to the state encoding; for the string recognizer this is a shift-register redesign with no explicit progress component.
    \end{itemize}
    \item At each iteration, contrast two verification workflows against the \emph{same} $\Phi_{\mathrm{dyn}}$:
    \begin{itemize}
        \item \textbf{Assertional:} re-check the compiled fragment on the new transition and readout tables (on finite spaces, equivalently search/verify a Def.~4.3 witness).
        \item \textbf{Classical:} re-derive and prove a structure-specific Wymore homomorphism $h=(h_S,h_I,h_O)$.
    \end{itemize}
\end{enumerate}
Examples are adapted from Wymore's discrete-system illustrations \citep{Wymore1993}. The ones-counter is pedagogical (mild elaborations, projections remain obvious). The string recognizer is the flagship value demonstration: instrumentation at v2 keeps a trivial projection, while the v3 shift register forces a non-trivial $h_S$. The real accumulator shows that the same maintenance pattern extends to real-valued state under a discrete clock. The case studies are qualitative on verification effort---they exhibit a stable fragment beside evolving buildables; they do not measure wall-clock cost.

Taken together, the examples compile $\Phi_{\mathrm{dyn}}$ once per reference table, re-check that fragment across lifecycle iterations, and---especially for the recognizer's shift-register refactor---contrast that re-check with the classical obligation to rebuild $h_S$.
