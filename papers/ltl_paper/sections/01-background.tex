\subsection{Discrete Systems and Cotyledons}
In Wymore's framework, a discrete system (denoted $\mathrm{DSYSTEM}$ in \citet{Wymore1993}) is a deterministic Moore-type state machine defined by a quintuple $Z=(S,I,O,\delta,\rho)$ consisting of a nonempty state set $S$, an input alphabet $I$, an output alphabet $O$, a next-state transition function $\delta:S\times I\to S$, and a state readout function $\rho:S\to O$. Here ``discrete'' refers to the discrete time scale $T=\mathbb{N}$; the state and port sets $S$, $I$, and $O$ may be either finite (as in physical digital hardware \citep{Wymore1993,BaierKatoen2008}) or countably infinite (as in idealized mathematical specifications with unbounded counters). Given an initial state $s_0\in S$ and an input trajectory $f:T\to I$, iterating $\delta$ from $s_0$ generates a unique state trajectory $g(t)$ (Wymore's $\mathrm{STZ}(Z,s_0,f)(t)$) and a corresponding boundary output trajectory $y(t)=\rho(g(t))$ (Wymore's $\mathrm{OTZ}(Z,s_0,f)(t)$). Because $\rho$ is a function of the current state $g(t)$ alone, every Wymorian discrete system obeys Moore causality: an external input $f(t)$ arriving at tick $t$ first affects the next state $g(t+1)=\delta(g(t),f(t))$ and can therefore influence the boundary output no earlier than tick $t+1$.

T3SD organizes a system design problem around three mathematical spaces, called \emph{cotyledons} after their leaf-shaped depiction in Wymore's diagrams \citep{Wymore1993}:
\begin{enumerate}
    \item \textbf{Functionality Cotyledon $\mathrm{CTL}(IOR)$.} An input/output requirement is a 6-tuple $IOR=(OLR,IR,ITR,OR,OTR,ER)$, where $OLR$ specifies the operational length (defining the requirement's time scale $T_{IOR}\subseteq\mathbb{N}$), $IR$ and $OR$ are the boundary input and output alphabets, $ITR\subseteq IR^T$ and $OTR\subseteq OR^T$ are the sets of admissible input and output trajectories---where $A^T$ denotes the set of all functions (trajectories) from the time scale $T$ to the alphabet $A$ (written $\mathrm{FNS}(T,A)$ in \citet{Wymore1993})---and $ER\subseteq ITR\times OTR$ is the eligibility relation pairing each admissible input trajectory $f\in ITR$ with its set of acceptable output trajectories $ER(f)\subseteq OTR$. A \emph{functional system design} $D_f=(Z_f,s_0,T_f)\in\mathrm{CTL}(IOR)$ (the Functionality Space Requirement, $\mathrm{FSR}(IOR)$, Definition~6.42 of \citet{Wymore1993}) packages a discrete system $Z_f$ on boundary alphabets $(IR,OR)$, a designated initial state $s_0$, and a nonempty \emph{operational time scale} $T_f\subseteq T_{IOR}$ (the set of discrete clock ticks over which boundary trajectories are evaluated) such that for every $f\in ITR$ (and any input extension agreeing with $f$ on $T_{IOR}$), the output trajectory generated by $Z_f$ from $s_0$ agrees on $T_f$ with some eligible trajectory $g\in ER(f)$. Wymore shows that $\mathrm{CTL}(IOR)$ is either empty (when $IOR$ violates Moore causality) or infinite, because once a single realizing state machine exists, any state re-encoding or state-space elaboration yields another distinct member of $\mathrm{CTL}(IOR)$ (Theorem~6.64 in \citet{Wymore1993}).
    \item \textbf{Buildability Cotyledon $\mathrm{CTL}(TYR)$.} A technology $TYR$ is a nonempty catalog of available discrete component systems (such as hardware registers, sensors, clocks, communication buffers, or software modules). Assembling a coupled architecture from component parts requires specifying both a \emph{bill of materials} and an \emph{interface wiring diagram}. Wymore formalizes this pair as a System Coupling Recipe $SCR=(VSCR,CSCR)$, where $VSCR$ (the vector of systems in the coupling recipe) lists the component discrete systems selected for the assembly and $CSCR$ (the connectivity of the system coupling recipe) is a one-to-one relation pairing internal component output ports to component input ports. Any component ports left unwired by $CSCR$ remain exposed at the exterior boundary as the unconnected system inputs and outputs (denoted $\mathrm{UISCR}(SCR)$ and $\mathrm{UOSCR}(SCR)$ in \citet{Wymore1993}). Synchronous composition of the wired components produces a unique coupled \emph{resultant} discrete system $Z_b=\mathrm{RSY}(SCR)$. The buildability cotyledon $\mathrm{CTL}(TYR)$ (the Buildability Space Requirement, $\mathrm{BSR}(TYR)$, Definition~7.38 of \citet{Wymore1993}) is generated by the catalog $TYR$ alone and consists of all buildable system designs $D_b=(Z_b,SCR)$ across all valid coupling recipes $SCR$ whose components $VSCR$ are drawn from $TYR$.
    \item \textbf{Implementability Cotyledon $\mathrm{CTL}(IOR,TYR)$.} Informally, we may understand the implementability cotyledon as the overlap between functionality and buildability, i.e., those designs that both satisfy the input/output requirement and are constructible from the available technology. Formally, because functional designs specify abstract boundary behavior whereas buildable designs specify coupled component architectures with potentially different state spaces and port structures, $\mathrm{CTL}(IOR,TYR)$ (the Implementability Space Requirement, $\mathrm{ISR}(IOR,TYR)$, Definition~7.64 of \citet{Wymore1993}) is defined as the set of pairs $(D_f,D_b)\in\mathrm{CTL}(IOR)\times\mathrm{CTL}(TYR)$ linked by Wymore's \emph{implementation} relation ($\mathrm{IMPSY}$, Definition~5.71) \citep{Wymore1993}.
\end{enumerate}
Throughout this paper, when the initial state $s_0$, operational time scale $T$, and coupling recipe $SCR$ are clear from context, we identify a functional design $D_f=(Z_f,s_0,T)$ with its underlying system $Z_f\in\mathrm{CTL}(IOR)$ and a buildable design $D_b=(Z_b,SCR)$ with its coupled resultant $Z_b=\mathrm{RSY}(SCR)\in\mathrm{CTL}(TYR)$, writing implementable pairs in $\mathrm{CTL}(IOR,TYR)$ as $(D_f,Z_b)$.

\subsection{System Modes, Homomorphisms, and Implementation}
\label{sec:background-modes-hom}
We would rarely expect a buildable resultant $Z_b=\mathrm{RSY}(SCR)$ to satisfy an abstract functional model $Z_f\in\mathrm{CTL}(IOR)$ by direct state-space equality, as the two systems will almost always have different state spaces. In practice, a coupled architecture contains implementation details that do not appear in an idealized functional specification: built-in-test (BIT) and fault-monitoring states, sensor-polling and packet-framing cycles, redundancy warm-up modes, communication buffers, or unused port encodings. Conversely, an idealized functional model may be stated over an infinite state space (such as an unbounded counter), whereas any physical machine operates within a bounded hardware capacity.

Wymore introduces two concepts to relate buildable resultants and functional models:
\begin{itemize}
    \item \textbf{System Mode ($\mathrm{SYSMO}$, see Definition~5.6 in \citet{Wymore1993}).} A discrete system $Z_m=(S_m,I_m,O_m,\delta_m,\rho_m)$ is a \emph{system mode} of a buildable system $Z_b=(S_b,I_b,O_b,\delta_b,\rho_b)$, written $Z_m\in\mathrm{SYSMO}(Z_b)$, if $Z_m$ embeds into $Z_b$ via injective maps on states, inputs, and outputs such that each step of $Z_m$ corresponds to a well-defined trajectory segment of $Z_b$ within an invariant operational regime (for example, restricting $Z_b$ to its reachable post-reset states, an active operational phase, or a bounded operating envelope). Every system is trivially a mode of itself via its primary self-mode.
    \item \textbf{System Homomorphism ($\mathrm{HIMSY}$, see Definition~4.3 in \citet{Wymore1993}).} A functional system $Z_f=(S_f,I_f,O_f,\delta_f,\rho_f)$ is a \emph{homomorphic image} of $Z_m$ (written $Z_f\in\mathrm{HIMSY}(Z_m)$) if there exist \emph{surjective} maps $h_S:S_m\twoheadrightarrow S_f$, $h_I:I_m\twoheadrightarrow I_f$, and $h_O:O_m\twoheadrightarrow O_f$ (denoted $\mathrm{HS}$, $\mathrm{HI}$, and $\mathrm{HO}$ in \citet{Wymore1993}) that commute with state transitions and readouts at every state $x\in S_m$ and input $p\in I_m$:
    \begin{equation}
        h_S(\delta_m(x,p)) = \delta_f(h_S(x),h_I(p)), \qquad h_O(\rho_m(x)) = \rho_f(h_S(x)).
        \label{eq:wymore-hom-def}
    \end{equation}
\end{itemize}
By Definition~5.71 in \citet{Wymore1993}, a buildable resultant $Z_b$ \emph{implements} a functional system $Z_f$ (written $Z_f\in\mathrm{IMPSY}(Z_b)$) if and only if $Z_f$ is a homomorphic image of at least one system mode $Z_m\in\mathrm{SYSMO}(Z_b)$. Wymore's Theorem~6.58 further establishes that when $Z_m$ and $Z_f$ share the boundary alphabets $(IR,OR)$ with identity port maps ($h_I=\mathrm{id}_{IR}$, $h_O=\mathrm{id}_{OR}$), any homomorphism $h_S:S_m\twoheadrightarrow S_f$ preserves $IOR$ satisfaction across corresponding initial states:
\begin{equation}
    \mathrm{SatisfiesIOR}(Z_m,IOR,s_0,T) \Longleftrightarrow \mathrm{SatisfiesIOR}(Z_f,IOR,h_S(s_0),T).
    \label{eq:thm-658-preview}
\end{equation}

\subsection{Temporal Logics and Model Checking}
\label{sec:background-ltl}
Linear Temporal Logic (LTL) and its first-order extensions provide an assertional language for expressing properties of time-indexed trajectories \citep{Pnueli1977,MannaPnueli1995,BaierKatoen2008,VardiWolper1986,Thomas1990}. Rather than specifying desired behavior constructively by defining a concrete state set and transition table, a temporal formula characterizes the admissible infinite or finite traces directly using Boolean connectives ($\wedge,\vee,\neg,\rightarrow$) and temporal modalities such as $G\,\varphi$ (``always $\varphi$''), $X\,\varphi$ (``at the next tick, $\varphi$''), and $F\,\varphi$ (``eventually $\varphi$''), summarized in Table~\ref{tab:ltl-operators}. For example, in a subsystem with a binary request input $\mathit{req}(t)\in\{0,1\}$ and acknowledge output $\mathit{ack}(t)\in\{0,1\}$, the safety formula $G(\mathit{req}=1 \rightarrow X(\mathit{ack}=1))$ asserts that every request arriving at tick $t$ produces an acknowledgment at the next clock tick $t+1$, whereas the liveness formula $G(\mathit{req}=1 \rightarrow F(\mathit{ack}=1))$ requires that every request be acknowledged at some future tick $\tau\ge t$. As developed in Section~\ref{sec:methodology}, we use temporal formulas in two complementary ways: to state boundary input/output requirements directly as trajectory assertions ($\Phi_{IOR}$), and to compile the transition and readout tables of a reference state machine $Z_{\mathrm{ref}}$ into step-local $G$/$X$ safety clauses ($\Phi_{\mathrm{dyn}}(Z_{\mathrm{ref}})$).

In formal verification, temporal formulas are evaluated over a \emph{Kripke structure}: a directed state-transition graph whose nodes represent system configurations, whose edges represent one-step transitions, and whose node labels record the atomic propositions (such as current state, input, and output values) that hold at each configuration \citep{BaierKatoen2008}. Kripke structures are the standard mathematical representation consumed by automated model checkers. Whenever a Wymorian discrete system mode $Z_m$ has finite state, input, and output sets, its execution graph defines a finite Kripke structure whose paths are sequences of $(g(t),f(t),y(t))$ triples. Deciding whether every run of a finite-state system satisfies an LTL formula ($Z_m\models\varphi$) is PSPACE-complete \citep{SistlaClarke1985} and is supported by established explicit-state checkers (which traverse reachable states directly), symbolic checkers based on binary decision diagrams (BDDs, canonical compressed graph representations of Boolean transition relations \citep{BurchClarkeMcMillanDill1992}), and SAT/SMT-based model checkers \citep{BiereCimattiClarkeZhu1999,BaierKatoen2008,deMouraZ32008}.

\subsection{Related Work}
\label{sec:related-work}
Several lines of research across systems engineering, formal verification, and computational complexity inform the approach developed in this paper.

Within the MBSE literature, recent work has revisited Wymore's T3SD to provide a rigorous systems-theoretic foundation for modern modeling practices. Salado and Wach \citep{salado2019wymore,salado2019mbse} demonstrated how Wymorian input/output requirements can ground True Model-Based Requirements (TMBR) in SysML without conflating problem-space boundary requirements with internal solution architectures, while Wach et al.\ \citep{wach2021devs} connected Wymore's discrete systems to Discrete Event System Specification (DEVS) \citep{ZeiglerPraehoferKim2000}. Mainstream SysML/UML practice, however, lacks a native mathematical notion of homomorphism between problem-space boundary requirements and coupled buildable resultants, so architectural verification often remains descriptive or else exports the entire diagram into an external semantic substrate such as Petri nets or transition systems \citep{Jensen1997,ZeiglerPraehoferKim2000}. T3SD-oriented modernization efforts preserve the separation between the functionality and buildability cotyledons; however, they still rely on Wymore's classical constructive $\mathrm{IMPSY}$ definitions when certifying that a coupled architecture implements a requirement. The present paper retains Wymore's coupling algebra $\mathrm{RSY}$ and system modes $\mathrm{SYSMO}$ and automates the implementability check through temporal specifications $\Phi_{IOR}$ and $\Phi_{\mathrm{dyn}}$.

Contract-based design and interface theories provide a complementary vocabulary for boundary requirements. Assume/guarantee contracts and interface automata typically partition concerns into environmental assumptions and system guarantees \citep{BenvenisteEtAl2018,deAlfaroHenzinger2001}. A Wymorian $IOR$, by contrast, packages admissible input trajectories $ITR$ together with an eligibility relation $ER\subseteq ITR\times OTR$ that pairs each admissible input with its acceptable outputs. Expressing that eligibility relation as a boundary temporal specification $\Phi_{IOR}$ makes $IOR$ satisfaction tool-checkable in the spirit of contract-style boundary verification, while retaining Wymore's Moore causality at the readout boundary; we do not identify $IOR$s with assume/guarantee contracts, but rather note that $\Phi_{IOR}$ supplies a temporally executable account of the same trajectory-level intent that contracts address at interfaces.

In formal methods and concurrency theory, temporal logic safety fragments have long been used to characterize step-local transition invariants \citep{Sistla1994,MannaPnueli1995}, and characteristic-formula constructions encode operational state machines into modal or temporal logic formulas up to simulation or bisimulation equivalence \citep{Milner1989,GrafSifakis1986,SteffenIngolfsdottir1994,AcetoEtAl2012}. Those constructions typically target action-labeled transition systems and often rely on modal calculi to characterize branching or weak behavioral equivalences. From an algebraic perspective, state-based dynamical systems can be modeled as \emph{coalgebras}---structures equipped with a state observation (readout) map and a next-state transition map out of a state set $S$, such as $(\rho,\delta):S\to O\times S^I$ for a deterministic Moore machine---for which structure-preserving maps (called \emph{bounded morphisms}) obey the exact same readout and transition commutation equations~\eqref{eq:wymore-hom-def} as Wymore's surjective system homomorphisms \citep{Rutten2000,BlackburnDeRijkeVenema2001}. Because T3SD systems are deterministic Moore machines with synchronous port-based coupling ($\mathrm{RSY}$) and operational modes ($\mathrm{SYSMO}$) that preserve step-local autonomous behavior, the compiled dynamics fragment $\Phi_{\mathrm{dyn}}$ is intentionally a step-local $G$/$X$ safety fragment mirroring Wymore's static homomorphism axioms (Definition~4.3 in \citet{Wymore1993}), rather than a full characteristic formula for branching bisimulation. Prior characteristic-formula results do not, however, connect trajectory-based $IOR$s, system modes, and coupling recipes within the tricotyledon framework, a gap that this paper addresses.

Finally, our work connects to formal refinement mappings in computer science and the computational complexity of finding homomorphisms. In formalisms such as TLA+ and hierarchical I/O automata, refinement mappings allow a concrete implementation to take multiple internal ``stuttering'' steps during a single step of an abstract specification \citep{AbadiLamport1991,LynchTuttle1987,Lamport2002}. By contrast, Wymore's implementation relation is step-synchronous, equating one clock tick of the operational mode $Z_m$ with one clock tick of the functional design $Z_f$: intermediate execution details are accommodated by first isolating an operational system mode $Z_m\in\mathrm{SYSMO}(Z_b)$ and then exhibiting a surjective step-synchronous homomorphism onto $Z_f$. The compiled fragment $\Phi_{\mathrm{dyn}}$, which retains the next-step operator $X$, is therefore the exact temporal counterpart of classical T3SD, whereas multi-rate and stuttering relaxations are deferred to future work. Deciding whether a surjective homomorphism exists between finite relational structures or transition systems is NP-hard in general \citep{HellNesetril1990,BodirskyKaraMartin2012}, and maintaining an explicit state projection $h_S:S_m\twoheadrightarrow S_f$ is fragile under architectural revision. Translating $IOR$s and reference dynamics into temporal specifications evaluated over finite buildable system modes therefore replaces manual homomorphism construction with decidable LTL and SAT-based verification \citep{SistlaClarke1985,BaierKatoen2008}.
