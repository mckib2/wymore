\subsection{Matched Ticks}
\label{sec:case-ticks}

A homomorphism equates one tick of the build with one tick of the reference. The head in Section~\ref{sec:case-machine} makes the modeling obligation obvious: sense, then act, is two ticks. A minimal counterexample isolates the resulting obstruction.

Staged implementations require a way to distinguish behavioral errors from
mismatched timing abstractions.

\begin{proposition}[Matched-tick requirement]
\label{prop:matched-ticks}
Let the reference be a bit that flips on every driven tick, and let the
implementation carry sense and act phases while flipping only on act ticks.
The implementation fails the one-tick dynamics fragment. If the reference is
restated with two ticks per flip, the implementation and reference are
isomorphic.
\end{proposition}

\begin{proof}[Proof sketch]
Readout preservation forces the state map to ignore the phase. On a sense tick,
the implementation holds while the one-tick reference flips, so transition
preservation would equate a reference bit with its negation. With the two-tick
reference, the phase and bit coordinates correspond directly and the identity
boundary maps complete an isomorphism.
\end{proof}

The corresponding finite queries are respectively unsatisfiable and
satisfiable. A relation allowing $k$ build ticks per reference tick would
define a different conformance relation.
