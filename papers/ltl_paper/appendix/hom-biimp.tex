\section{Correspondence Proofs}
\label{app:hom-biimp}

The main text uses two correspondence results. The first follows by unfolding
the definition of IOR satisfaction. The second rests on a simple observation:
a system's one-step table equations and the corresponding clauses along every
run contain the same information, provided that a run may begin in every
implementation state. We give both arguments here.

\subsection{The boundary correspondence}

Fix an IOR
\[
  R=(OLR,IR,ITR,OR,OTR,ER)
\]
and let $T_R$ be its time scale. Its characteristic fragment retains exactly
the data used to test a system at the boundary:
\[
  \Phi_R=(T_R,ITR,A_R),
  \qquad A_R(f,g)\ \Longleftrightarrow\ g\in ER(f).
\]
For a system $Z$, designated state $s_0$, and nonempty $T\subseteq T_R$, the
assertion $Z,s_0,T\models_{IO}\Phi_R$ says the following. Choose an admissible
input $f\in ITR$, and then choose any complete input $h$ that agrees with $f$
on $T_R$. The output generated by $Z$ from $s_0$ on $h$ must agree on $T$
with some trajectory $g$ allowed by $A_R(f,\cdot)$.

Substituting the definition of $A_R$ changes ``allowed by
$A_R(f,\cdot)$'' into ``belongs to $ER(f)$.'' Every other clause is already
the corresponding clause of Wymore's $SatisfiesIOR$: $T$ is nonempty,
$T\subseteq T_R$, $f$ belongs to $ITR$, and $h$ is an agreeing extension.
Thus, for every IOR and every choice of $Z,s_0,T$,
\[
  Z,s_0,T\models_{IO}\Phi_R
  \quad\Longleftrightarrow\quad
  SatisfiesIOR(Z,R,s_0,T).
\]
The two criteria are identical. A member of $\mathrm{AFSR}(\Phi_R)$ and the corresponding member of
$\mathrm{FSR}(R)$ therefore carry the same system, designated state, and time
scale. Only the name of the satisfaction certificate changes. Replacing that
certificate in either direction gives the canonical bijection
\[
  \mathrm{AFSR}(\Phi_R)\simeq\mathrm{FSR}(R).
\]

\subsection{The dynamics correspondence}
\label{app:hom-setup}

We now prove Theorem~\ref{thm:dynamics-characterization}. Write the reference
and implementation systems as
\begin{align*}
Z_{\mathrm{ref}}
  &= (S_{\mathrm{ref}},I_{\mathrm{ref}},O_{\mathrm{ref}},
      \delta_{\mathrm{ref}},\rho_{\mathrm{ref}}),\\
Z_{\mathrm{impl}}
  &= (S_{\mathrm{impl}},I_{\mathrm{impl}},O_{\mathrm{impl}},
      \delta_{\mathrm{impl}},\rho_{\mathrm{impl}}).
\end{align*}
Their state and interface types need not be the same. Candidate maps therefore
have the directions
\[
 h_S:S_{\mathrm{impl}}\to S_{\mathrm{ref}},\qquad
 h_I:I_{\mathrm{impl}}\to I_{\mathrm{ref}},\qquad
 h_O:O_{\mathrm{impl}}\to O_{\mathrm{ref}}.
\]
All three maps are required to be surjective. Write $\bar h_I$ and $\bar h_O$
for their extensions to optional inputs and outputs, with
$\mathrm{none}$ mapped to $\mathrm{none}$.

A Wymore homomorphism is precisely such a triple satisfying, for every
implementation state $x$ and optional implementation input $q$,
\begin{align}
  \bar h_O\!\left(\rho_{\mathrm{impl}}(x)\right)
    &= \rho_{\mathrm{ref}}\!\left(h_S(x)\right),
    \label{eq:hom-readout-static}\\
  h_S\!\left(\delta_{\mathrm{impl}}(x,q)\right)
    &= \delta_{\mathrm{ref}}\!\left(h_S(x),\bar h_I(q)\right).
    \label{eq:hom-step-static}
\end{align}
Equation~\eqref{eq:hom-readout-static} says that observing and then abstracting
gives the same answer as abstracting the state and then observing.
Equation~\eqref{eq:hom-step-static} says the same for one step of behavior.
These are the two commuting diagrams in Definition~4.3 of
\citet{Wymore1993}.

Now consider a run of $Z_{\mathrm{impl}}$. An initial state $s_0$ and an
optional-input trajectory $f$ determine state and output trajectories by
\begin{align}
  g(0)&=s_0, \label{eq:trace-init}\\
  g(t+1)&=\delta_{\mathrm{impl}}(g(t),f(t)),
    \label{eq:trace-step}\\
  y(t)&=\rho_{\mathrm{impl}}(g(t)).
    \label{eq:trace-readout}
\end{align}
At tick $t$, the atom $\mathit{refState}(s)$ means $h_S(g(t))=s$.
The four clause families in Table~\ref{tab:phi-dyn-fragment} can consequently
be read in two compact lines:
\begin{align}
  \bar h_O(y(t))
    &=\rho_{\mathrm{ref}}(h_S(g(t))), \label{eq:trace-readout-law}\\
  h_S(g(t+1))
    &=\delta_{\mathrm{ref}}(h_S(g(t)),\bar h_I(f(t))).
    \label{eq:trace-step-law}
\end{align}
The open- and closed-readout clauses are the two cases of
\eqref{eq:trace-readout-law}. The autonomous and guided clauses are the
$\mathrm{none}$ and $\mathrm{some}$ cases of
\eqref{eq:trace-step-law}. This compression is only notational; no clause has
been dropped.

The proof now reduces to the following bridge.

\begin{lemma}[Static laws and run clauses]
\label{lem:static-run-bridge}
Fix surjective maps $h_S,h_I,h_O$. The static
laws~\eqref{eq:hom-readout-static}--\eqref{eq:hom-step-static} hold at every
implementation state if and only if
\eqref{eq:trace-readout-law}--\eqref{eq:trace-step-law} hold at every tick of
every implementation run.
\end{lemma}

\begin{proof}
Suppose first that the static laws hold. At an arbitrary tick $t$, use
\eqref{eq:trace-readout} and then apply the readout law at the current state
$g(t)$:
\[
  \bar h_O(y(t))
  =\bar h_O(\rho_{\mathrm{impl}}(g(t)))
  =\rho_{\mathrm{ref}}(h_S(g(t))).
\]
This is \eqref{eq:trace-readout-law}. Likewise,
\eqref{eq:trace-step} followed by the transition law at $g(t)$ with input
$f(t)$ gives
\[
  h_S(g(t+1))
  =h_S(\delta_{\mathrm{impl}}(g(t),f(t)))
  =\delta_{\mathrm{ref}}(h_S(g(t)),\bar h_I(f(t))),
\]
which is \eqref{eq:trace-step-law}. Since the run and tick were arbitrary, all
four clause families hold.

For the converse, let $x$ be any implementation state. Begin a run at
$s_0=x$. At tick zero, $g(0)=x$, so
\eqref{eq:trace-readout-law} immediately gives
\[
  \bar h_O(\rho_{\mathrm{impl}}(x))
  =\rho_{\mathrm{ref}}(h_S(x)).
\]
This recovers the static readout law at $x$.

It remains to recover the transition law. Let $q$ be any optional
implementation input, and choose a run whose input at tick zero is $q$.
Equation~\eqref{eq:trace-step-law} at tick zero, together with
$g(0)=x$ and
$g(1)=\delta_{\mathrm{impl}}(x,q)$, gives
\[
  h_S(\delta_{\mathrm{impl}}(x,q))
  =\delta_{\mathrm{ref}}(h_S(x),\bar h_I(q)).
\]
This covers both an autonomous step $q=\mathrm{none}$ and a guided step
$q=\mathrm{some}(i)$. Because $x$ and $q$ were arbitrary, both static laws
hold everywhere.
\end{proof}

The quantification over initial states is important in the reverse direction:
it lets us place an arbitrary state $x$ at tick zero. If only one designated
initial state is admitted, the same argument recovers the static laws on the
reachable subsystem, but says nothing about unreachable states.

We can now finish the correspondence. If
$h=(h_S,h_I,h_O)$ is a Wymore homomorphism, its static laws hold by
definition, and Lemma~\ref{lem:static-run-bridge} shows that every run satisfies
the compiled fragment. Conversely, suppose
$Z_{\mathrm{impl}}\models_{\mathrm{dyn}}\Phi_{Z_{\mathrm{ref}}}$.
Satisfaction supplies surjective maps $h_S,h_I,h_O$ for which every run obeys
the clauses. The reverse half of the lemma recovers the two static laws, so
these maps form a Wymore homomorphism. Therefore
\[
  Z_{\mathrm{impl}}\models_{\mathrm{dyn}}\Phi_{Z_{\mathrm{ref}}}
  \quad\Longleftrightarrow\quad
  \exists\,h:Z_{\mathrm{impl}}\to Z_{\mathrm{ref}}
  \ \text{Wymore system homomorphism}.
\]

Surjectivity deserves one final comment. The equations alone describe a
behavior-preserving projection onto some part of the reference. Surjectivity
ensures that every reference state, input, and output is represented by the
implementation, as Definition~4.3 requires. In the clause presentation, it
also prevents a reference row from being satisfied only because no
implementation state ever projects to it.

Finally, let $Z_{\mathrm{ref}}$ be the system component of
$D_{\mathrm{ref}}\in\mathrm{FSR}(R)$, and let $Z_{\mathrm{impl}}$ be the
resultant of a buildable design. Satisfaction of the dynamics fragment now
supplies exactly the implementation witness needed to pair those two designs
in $\mathrm{ISR}(R,TYR)$. The proof concerns the compiled readout and
one-step clauses. Temporal properties outside that fragment, including
eventuality, require their own arguments.
